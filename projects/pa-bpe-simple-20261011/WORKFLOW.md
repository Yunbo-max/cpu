# GitHub 持久存档与一次性运行缓存

用户授权（2026-10-12）：将 PA-BPE 历史放入 `Yunbo-max/cpu`；每次按需下载执行，上传结果并核验后删除本项目临时缓存。此授权替代旧任务中以 Library 为首选写回目的地的条款，其他科研、资源、盲化和报告约束不变。旧 Library 版本作为迁移回退副本保留。

## 恢复

1. 只用原有 PA-BPE 调度。先获取 GitHub 最新 `main`，记录其完整 commit SHA；查看本目录的 `CURRENT.json`、本协议、研究检查点、manifest、累计用量、alerts/health 和未完成作业身份。不得从过时本地副本启动。
2. 使用新的、带本轮身份的短期目录；先检查是否已有本项目 writer 或科学作业。只有核实失活后才能接管旧锁。共享宿主上的其他项目锁和进程不可修改。
3. 使用 `git clone --filter=blob:none --no-checkout --depth=1` 与 sparse checkout，仅检出本目录的元数据、脚本及本次必要的 state 子路径。小规模启动时也可完整检出本项目的 state，但不默认拉取 archives 或其他项目。保留 history/manifest 中所有条目，稀疏缺失不等于删除。
4. 在已取得的本项目目录运行 `python3 cache_io.py verify-state --allow-partial`，只接受其报告为已验证的文件。首次完整恢复或完整归档核验使用 `verify-state`，不带 partial。所有实验输入都必须实际存在且其哈希通过；仅有目录不算恢复。
5. 仅需历史或 raw 数据时检出 `archives/index.json` 与索引指定的块，执行 `python3 cache_io.py restore-archive ARCHIVE_SHA256 --output /absolute/new/path.zip`。输出文件必须原先不存在；逐块和整包校验失败即停止。`incomplete-transfer-forensic-only` 是失败下载证据，不能用于恢复实验。当前下一研究动作只需要盲哈希索引，不需要打开 raw 确认文本。
6. 旧日志中的绝对路径是历史证据。新执行窗口须绑定当前实际路径与新身份，不直接复用旧 PID、旧 deadline 或旧 command cwd，不修改历史日志伪造连续驻留。

## 执行与提交

7. 继续 continuous_research，无项目累计时间上限，所有用量和失败连续记账。保持 CPU only、1 科学进程/1 线程、科学单命令不超过 120 秒；每有限批至多 12 attempts、科学 wall 不超过 600 秒、主动宿主窗口不超过 30 分钟。每轮测实际共享容量，保留原有 RSS 约束；不改变其他项目或共享依赖。
8. 新结果、命令、退出码、CPU/wall/RSS、来源/hash、失败、下一步和审查写入本项目 state。更新研究 manifest、generation 与 `CURRENT.json`；对稀疏未检出的旧文件保留原哈希，不可因缺失而删库。既有历史文件保留原字节，新的更正追加记录。增量 Git 提交无需每轮重复上传整份 ZIP。
9. 暂存时使用 `GIT_NO_LAZY_FETCH=1 git -c remote.origin.promisor=false add -- <明确路径>`（本宿主已验证可避免 partial clone 对新对象的无效远端请求）。只 `git add` 本项目明确的新增/更新路径，不在稀疏工作树使用不受限的删除或覆盖。提交前重新 fetch。若其他项目更新了 main，保留其提交并在最新 main 上重放本项目提交；若同一项目 state 变了，停止提交、重新恢复并协调唯一 writer。禁止 force push。
如果宿主 git 无写凭证，可使用同目录 `publish.py` 与当前平台的 HostedAppsClient，通过已连接 GitHub 的真实 connector ID 上传；不得导出或猜测凭证。先以 `--upload-only` 分批上传，再使用 `--publish --expected-project-tree <恢复时项目树SHA>` 原子提交。初次导入使用 `absent`；后续必须绑定实际项目树。`--receipts` 必须在发布树外，批次可恢复且每个 blob 的 Git SHA 都要匹配。默认原始文件块不超过 4 MiB；脚本本身不删除任何本地文件。

10. `git push` 或受保护的 connector 提交成功后，从远端重新 fetch 到独立临时验证目录，绑定刚提交的完整 SHA。核对目标 SHA 是远端 main 的当前或祖先提交，验证全部新增/变更文件的 SHA256 和规范 manifest。上传返回成功本身不构成删除许可。完整初次迁移还必须校验每个 archive 块、整包重组及所有初始 state 文件。

## 清理

11. 先确认科学作业全部终态、reservation 已结算或如实记录，writer 已释放；把远端 commit、核验时间、范围、哈希以及用量写入持久回执。
12. 只有实际远端字节通过核验，且本地文件自核验后未变化，才删除该轮明确登记的 PA-BPE 临时目录、数据、虚拟环境、克隆与验证副本。不能删除 workspace 根、其他项目、仍有活进程使用的目录或未上传失败证据。
13. 上传失败、版本冲突、核验失败或作业身份未知时，保留本地唯一证据并立即报告，不执行清理；可以按既有身份保存到原 Library 回退检查点，但不能让两份规范状态静默分叉。
14. 删除磁盘文件可释放临时存储及部分相关页缓存，并不等于释放全部进程 RAM，也不扩大宿主内存上限。禁止全局 drop_caches 或终止其他项目以腾空间。

本协议不改变开发/确认隔离，不打开确认结果来调参，不重跑已完成实验，不以一次迁移或单个候选的完成停止持续研究。

## 内存不足时等待再跑

用户补充授权（2026-10-12）：内存暂时不足时先等待，够用后继续；持续跑不了时明确报告。启动科学命令前，实测共享硬上限、当前占用与剩余容量，对照已测或估计的实验 RSS 并保留合理余量。余量不足时不启动可能 OOM 的实验，保存状态，以不超过 60 秒的有界等待间隔重新测量。当前宿主窗口内恢复容量即可继续；窗口结束仍不足，则保存观测与阻塞记录，由原任务接续重试，不因暂时内存不足停用持续研究。

等待时可以做低内存的必要阅读、数学或源码核验，但不能算作实验进展。只能释放本项目已验证可恢复的缓存与闲置进程；禁止终止他人任务或清理全局页缓存。连续等待后仍无法满足实验实际需求时，用中文报告具体实验、需求与余量、观测时间、已做的有限修复和下一动作。

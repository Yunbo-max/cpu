# R007: does local reprojection optimization remove the oracle rotation edge?

Development gate on the exposed R006 full correspondences; no new solver or paper claim. R006 compares minimal RANSAC models without non-minimal refinement. PoseLib's official focal-unknown absolute-pose estimator supports LO-RANSAC followed by nonlinear refinement; the current R006 P4Pf wrapper did not invoke that full pipeline. This R007 isolates the refinement question before implementing a full external baseline.

Derivation: on fixed 2D–3D inliers, minimize robust reprojection residuals `rho(||pi_f(R X_i+t)-y_i||)`. For the visual P4Pf arm optimize 3 rotation parameters, 3 translation parameters and log focal. For the impossible oracle arm preserve `R=Ry(theta)Rxz_GT`, optimizing only theta, translation and log focal. Focal is unknown in both arms; equal 3-pixel initial inlier threshold and `soft_l1` residual with 3-pixel scale, max 100 function evaluations. Preexisting R006 output selects the initial maximum-consensus model. A shared all-match re-score after refinement records whether model errors and inliers improve or regress. Predictions: if P4Pf's larger rotation error is merely lack of refinement, its rotation gap should shrink; if the oracle still wins rotation but loses center/focal, gravity information creates a metric tradeoff rather than broad pose dominance. Either outcome remains unable to establish a real-sensor method.

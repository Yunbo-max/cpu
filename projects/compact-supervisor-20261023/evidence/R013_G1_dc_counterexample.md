# R013 G1: Ordinary s-t graph maxflow is not DC electrical transfer capability

Research science parent 79b064db2ecfe014a945e7284e16f41678739d3c. Scientific parent leaf G1 (GRAPH), no new physical-theory claim.

Actual CPU test: triangle physical grid with 3 buses (s,mid,t), unit susceptance and thermal capacity 1 on each of (s,mid), (mid,t), (s,t). Inject transfer T at s and withdraw T at t (mid has zero net injection), set phase theta_t=0. DC linearized lossless model yields theta_s=2T/3, theta_mid=T/3 and flows (s,t)=2T/3, (s,mid)=(mid,t)=T/3. Each line capacity=1 therefore T_DC <= min(3/2,3,3)=3/2. The ordinary network transport problem can independently route 1 on direct path s-t and 1 along the two-hop path; maxflow=2.

Delete direct physical line (s,t): DC transfer limit is now T<=1, while ordinary graph maxflow becomes 1. Hence normal network-flow sensitivity predicts a loss of 2-1=1, whereas physically constrained DC transfer sensitivity predicts 3/2-1=1/2, a factor-2 difference. This classical difference is explicitly recognized in transmission modeling: PyPSA https://docs.pypsa.org/latest/user-guide/optimization/power-flow/ applies Kirchhoff voltage/current constraints/linear PTDF, while network flow/transport models omit impedance and Kirchhoff loop constraints, e.g. https://doi.org/10.1016/j.apenergy.2022.118859. The 2024 Baswana & Bhanja exact weighted fault mincut oracle https://doi.org/10.4230/LIPIcs.ICALP.2024.17 is a strong comparator for ORDINARY graph flow, not a DC contingency oracle.

NYISO P-54B official historical outage archive https://mis.nyiso.com/public/P-54Blist.htm has operational outages, but there is still no verified event-deduplicated legal CSV extract in this Work turn, no verified public PTID-to-network physical matching graph with reactance + thermal constraints, and no defensible use of simple s-t graph maxflow to predict grid deliverability. The mathematical counterexample is independent of this missing dataset.

DECISION: G1 await (not globally Park): no more novel-method or model training from the NYISO+ordinary-maxflow pairing without a matched physical model or a new independently sourced NON-electrical failure workload. The generic graph-fault coder is not logically refuted on other tasks; exact sparse tables, classical source coding and ICALP2024 weighted sensitivity oracle must be matched in any future reopening. Falsifier for this await: a valid, independently sourced model+events+observable with a fair strong-oracle comparison is actually demonstrated.

# N1 mathematical contract: avoid triviality and pre-existing probabilistic data exchange

Let S,S' be losslessly equivalent finite relational schemas with instance spaces D_S,D_S', and a *declared bijective* transformation T:D_S→D_S' modulo key renaming. For a true instance distribution P and learning pipeline L_{S,n} mapping n independently sampled full database instances into a generative probability measure, consider the random output measure L_{S,n}(D_n).

**Not a theorem / not original:** For any known bijection T and any generator G_S, define G_{S'}=T_#G_S. Then T_#G_S=G_{S'} by definition. This provides exact covariance of distributions without any new ML contribution. Likewise if q' = q∘T^{-1}, then (q')_#(T_#G_S)=q_#G_S automatically. These are algebraic transport identities, closely within 2011 probabilistic data exchange and 2012 functorial data migration. Merely drawing the commuting square has almost ZERO novelty value.

**Harder source-dependent target (CONJECTURE, no empirical or formal originality guarantee):** Given independently trained models L_{S,n} and L_{S',n} with different factorizations, preprocessing and sample/negative examples, can one design a schema-agnostic learning rule with `E[d_Q(q_#L_{S,n}(D_n), (q∘T^-1)_#L_{S',n}(T(D_n)))]≤ε_n` over a meaningful query family Q, with ε_n controlled uniformly over a class of validated lossless normalizations T and n? Query family and metric must be specified (e.g. aggregate count distributions on entity-keyed full database instances). Account for multi-row join multiplicity, bag semantics, NULL/SQL semantics, entity vs row sampling, approximate constraints, and whether training supplies T itself; without restrictions, impossible/unidentifiable cases arise.

**Conceptual falsifier:** If T is known at training and outputs can simply be conjugated, the proposed benefit vanishes unless one also proves a nontrivial representation-independent training efficiency, downstream query fidelity or robustness gain under limited compute/observations. If T is not identifiable because field mappings are unknown, identical observed schema documentation need not determine semantics, and a universal zero-defect guarantee cannot follow from schema syntax alone.

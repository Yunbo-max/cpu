# B09：更强精确查询实现推翻 B08 的速度结论

日期：2026-10-10。决策流程为固定版本 autonomous-rsi
`7af53173bbd69726877ca04fb77b9466ef1b839d`；Simple `.3` 仅承担
CPU 命令和回执。

## 问题

B08 在原生 Landmark 前512行上发现，经典 FD50 下界减少精确查询后，
相对“每次查询都重新做完整前缀 SVD”的基线获得 1.876×/1.729× 中位
CPU 比。B09 检验这个正结果是否能通过更强的精确查询实现：增量维护
(G_t=A_tA_t^\top)，精确查询只求前25个特征值并由总能量得到
top-k OPT。

## V1：真实失败

V1 同时用 Gram 特征向量重建 top-k 端点。12个运行的查询掩码、刷新
掩码和查询处 OPT 均与 B07/B08 一致，但12/12都没有通过冻结的损失轨迹
容差；原因是不同 LAPACK 路径/QR 选择了数值上不同的最优子空间端点。
因此 V1 的速度不能作为语义等价比较；最大归一化损失偏差为
(7.37\times10^{-5})。审计命令按预案退出1，失败和全部原始输出保留。

## V2：保持 B08 端点的修复

V2 不放宽阈值：每次查询用缓存 Gram 精确计算 OPT；只有真实刷新时才
调用与 B08 相同的 NumPy 完整 SVD 并取相同右奇异基。这样非刷新查询
避免完整 SVD，而两条策略对相同刷新都支付相同的端点 SVD 成本。

12/12 个 V2 运行通过全部语义检查：查询/刷新掩码、查询处 OPT、损失
轨迹、非刷新可行性和门控下界均符合 B07/B08 冻结参考；损失轨迹逐值
相同，查询处 OPT 最大归一化差为 (8.76\times10^{-16})。

|eta|baseline CPU 秒（三次）|FD50 CPU 秒（三次）|FD50 更快配对|中位 baseline/FD50|
|---:|---|---|---:|---:|
|0.01|15.556, 14.346, 14.093|15.083, 15.190, 15.168|1/3|0.944|
|0.1|6.299, 6.623, 6.020|7.641, 7.666, 7.560|0/3|0.824|

六个配对中 FD50 只快1次。eta=0.1 三次分别慢1.342、1.043、1.539 CPU
秒；eta=0.01 后两次分别慢0.844、1.075秒。B08 的正加速因此依赖较弱
的“每次查询完整 SVD”实现，不能推广成强精确基线下的速度优势。

相对 B08，V2 baseline 中位 CPU 分别从25.543降到14.346秒、从12.021
降到6.299秒；FD50 因刷新数不变且增加 Gram/FD 维护，中位 CPU 反而由
13.744升到15.168秒、由7.148升到7.641秒。

## 1024 行校准

原生 Landmark 前1024行、五个固定检查点（512/640/768/896/1024）的
Gram OPT 与完整 SVD 最大归一化误差为 (8.90\times10^{-16})。Gram
构建 CPU 0.202秒；1024点的特征值查询0.066秒、完整 SVD 0.374秒；
命令峰值 RSS 120540 KiB。该命令仅测特征值和资源，不包含连续策略、
端点向量/QR或5000行协议，不能据此宣称更大规模加速。

独立结果审查重新核验两份冻结清单（26+24个文件）、52个输出回执、

仍不构成独立实验确认。

这仍是同一公开开发前缀和进程重复，不是独立数据确认。缓存 Gram 是
标准线性代数实现优化，不是新方法；V2 负结果不否定 FD 证书或查询数
减少，只否定当前“FD50 带来强基线速度收益”的主张。刷新/输出 recourse
没有减少。

# B04 中文简报

本轮实际恢复并哈希核验了主 B03 四个原始包、B01 代码包、Landmark 压缩源及矩阵字节；B03 manifest 的 307 项无缺失或哈希错误。宿主实测 cgroup 为 8 CPU / 8 GiB，数值线程固定为 1。

真实运行了 7 个受限命令 attempt，累计命令 wall 112.514 秒、可直接量得的 CPU 下界 89.138 秒、峰值 RSS 359440 KiB，reservation 已归零。首先用 15 个回归状态验证近零分支，其中 11 个近零状态的旧/新投影完全一致。随后在真实 Landmark 前 128 行、(d=2704,k=25)、两个 eta、旧/新/full 六臂上两次执行版本化修复。

写盘缺陷已经修复：v2 与 v3 NPZ 都通过命令内 ZIP CRC、完整 `np.load` 自读、原子替换前后哈希一致性；历史损坏 NPZ 原样保留。两次六臂结果均为 0 证书违例，38/38 个实际近零求根调用回退到原 48 步二分。

但严格数值门槛没有通过。v2 独立命令审计的旧/新最大检查点投影差为 (2.59145\times10^{-8})，高于冻结阈值 (10^{-8})；把 Newton 后括号继续二分到 (2^{-40}) 的 v3 仍为 (2.49439\times10^{-8})。两版的更新/查询掩码、相对损失、累计 recourse、证书、正交性及显式残差等其余 11 项均通过。最大差异处不存在明显 rank-25/26 谱并列，损失相对差仅约 (5\times10^{-16})，说明更像递归状态微差累积，而不是单次标量根精度不足。

按相同失败最多两次实质修复的规则，本轮不再重跑、不事后放宽阈值，也没有越过门槛执行 512 行校准。下一动作是从完全相同的输入投影逐次比较旧/新求根，分离单步误差与递归放大，并测量更广泛 legacy fallback 的 CPU 代价，再决定修订或退役该加速求解器。整体项目仍为 `continuation_pending`；本轮不是新方法、独立确认、完整 Landmark 比较或论文 PASS。

执行器在 7 个 attempt 全部结算、reservation=0 后停止。一次结构化 continuation 回执先因枚举值错误被拒；修正时执行器已进入 stopped，故没有把 continuation 写入其内部 journal。该操作缺陷不影响已保存实验字节或科学结论；恢复时以本批检查点、调试卡和完整 runner receipts 为准，不恢复该已停止实例。
